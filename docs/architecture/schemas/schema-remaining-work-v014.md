# Partially implemented and missing schemas - Haze v0.14

Status baseline: **26 October 2026**, source commit **`2e13f4c`**. These sections were moved from [the implemented schema inventory](schema-implementation-status-v014.md); the implementation findings are unchanged.

Implemented validators, defined-only helpers, and storage contracts are listed in [Implemented schema inventory](schema-implementation-status-v014.md). This document contains the remaining partial and missing contract families.

## 1. Partially implemented architecture contracts

These rows describe incomplete feature families. The validators listed in [the implemented inventory](schema-implementation-status-v014.md#1-already-implemented) already exist; this section lists what still needs additional fields, a common contract, or wider integration.

| Feature / contract family                 | Existing implementation                                                                             | Still missing or limited                                                                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Capability metadata and readiness         | `capabilityCardSchema`, internal capability definitions and readiness reports                       | Complete public source/model/package/access/limits/checked-at metadata and independent readiness evidence dimensions, owner and expiry/recheck.   |
| Multi-phase programme grouping            | Assignment DAGs, plan revisions and predecessor runs                                                | An enduring programme grouping across phases.                                                                                                     |
| Literal p.7 control envelope              | Assignments, task events, agent actions, peer messages and controls distribute its responsibilities | No single schema with all eleven literal fields, including `brief_ref` and `control_ref`.                                                         |
| General identity/authorization policy     | Local principal/workspace identity, tool grants, artifact and World Model access checks             | A general workspace policy/access-classification grant contract beyond local same-origin operation.                                               |
| Resource/billing accounting               | Call/tool/artifact/assignment counts, byte/token caps and attempt outcomes                          | Priced spend, aggregate actual-token budgets and typed uncertain-charge amounts.                                                                  |
| Peer grants/messages/closure              | Durable channels/messages, revisions, traffic/expiry limits and history                             | Explicit permitted-content/reader/spend/tool policy, typed excerpt attachments, dedicated closure time/reason/outcome/unresolved issues.          |
| Common artifact metadata                  | Exact refs, producers, dependencies, timestamps, tool requirements and origins                      | Common access classification, retention, supersession and complete conditional expiry/recheck metadata.                                           |
| Original source preservation              | Text/CSV/JSON import and original-byte hash                                                         | Original JSON serialization is not retained; arbitrary PDF/binary import is unavailable.                                                          |

| Versioned evaluation and release evidence | Unit/fixture tests, evaluation cases and implementation reports                                     | Complete cross-capability benchmark/result and readiness/release evidence contracts.                                                              |

## 2. Not implemented in the general task engine

The names below are requirement labels, not claims that code identifiers with those names already exist. Related generic prose, dashboard records or imported quantities do not supply these missing typed domain/workflow contracts.

| Missing schema / workflow family                      | Required records or content                                                                                                                                                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| General exposure estimation                           | Population/time/location exposure, native support, assumptions and uncertainty.                                                                                                                                           |
| Health-impact estimation                              | Counterfactual/baseline, exposure-response method, population support, uncertainty and qualified review.                                                                                                                  |
| Causal/source attribution estimation                  | Appropriate causal method, counterfactual, transfer/applicability limits and independent qualification. Imported attributed effects are supported, but their upstream estimation is not.                                  |
| Preparedness/prevention/delivery plans                | Dependencies, responsible operator, rights, resources, checkpoints, reviewed proposals and independent delivery verification.                                                                                             |
| Pilot/experiment protocols                            | Hypothesis, population, outcomes, comparator, measurements, analysis, missingness, stopping rules and approvals.                                                                                                          |
| Programme implementation/evaluation/accepted learning | Planned/reported/verified delivery, deviations, observations, comparative estimates, causal limits and reviewed learning.                                                                                                 |
| Owner-adopted target                                  | Accountable owner, metric/scope/comparator and evaluation criterion.                                                                                                                                                      |
| Reviewed reusable H-MEM lessons                       | Eligibility, exact support, independent review, intended-use scope, expiry, capture/recall and support/access revalidation in the general task path.                                                                      |
| Authorized external effects                           | Effect payloads, grants/approval, exact reviewed content, dispatch/delivery/correction receipts and reconciliation; no alert/contact/purchase/dispatch/fund connectors. `permissionsSchema.effects` permits zero entries. |
| Notifications/alerts                                  | Recipient rights, conditions, exact content, scope/language, expiry/review and delivery/correction receipts.                                                                                                              |
| General monitoring subscriptions                      | Accountable requester, source/topic/area/period/purpose, access, cadence, quotas, cursor, catch-up, deduplication and routing.                                                                                            |
| General scheduled change-routing records              | Bounded ticks and revision/retraction/duplicate/late-arrival/source-lag/routing-lag handling in the task engine. Separate dashboard watchers are supporting only.                                                         |

World Model acceptance, holds, support revisions, lineage and current reads are deliberately **not** on this missing list: current code implements them within the stated research/accounting boundary.
