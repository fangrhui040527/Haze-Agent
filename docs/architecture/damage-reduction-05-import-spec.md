# External evaluation import specification

This engineering interface implements [Plan 05](damage-reduction-05-external-evaluation.md). The authoritative browser-safe schemas are in [`damage-reduction-evaluation.ts`](../../app/contracts/damage-reduction-evaluation.ts). A complete synthetic example builder is [`syntheticExternalEvaluationInput`](../../app/capabilities/damage-reduction-programmes/evaluation-fixtures.ts), with matching original expected-output and dossier builders. `npm run reduction:evaluation:verify` imports these examples through the real artifact API and retains their exact versions in its verification directory. The example is never a scientific reference case.

## Import order

1. Retain the programme's reviewed pilot registration and exact original/amended protocol. Keep the registration record ID, all amendment record IDs, action/deviation/verification record IDs and agreed rule versions.
2. Import the original external report, data references, independent scientific review and independently prepared numerical expected output through `POST /api/artifacts`. Keep each returned `{id, version, sha256}`. Structured payloads use JSON text; ordinary original documents may remain text artifacts. Wrapped receipts and verification evidence must retain exact original references.
3. Import `haze.reduction.external-evaluation-input.v1`, binding the exact programme, target/scope hashes, protocol, delivery and evidence references. This imported input cannot be produced by an agent assignment. The source analysis method/version and registered design name must match the selected protocol.
4. Optionally import `haze.reduction.scientific-qualification-dossier.v1` after the input exists. It binds the input's exact reference and repeats its method/design/scope/protocol/delivery/criterion/evidence declarations. Retain a named reference case, scientific owner, authors, independent reviewer, conflicts, applicability/prerequisites, material objections, limitations and uncertainty interpretation. The expected-output artifact binds programme/method/design/target/scope; it does not point back to the input, avoiding an immutable-reference cycle.
5. Save an explicit programme revision selecting `evaluation_input_ref` and `evaluation_dossier_ref`. Start `evaluation` with the exact retained `registration_id`. Import, selection and execution are separate actions.
6. Inspect the saved result, independent technical review and learning. If appropriate, append an explicit `evaluation_qualification` human attestation binding their exact result/review/dossier references. A retained decision is not an authority grant: use the server's current `evaluation.qualification` and `evaluation.claim` projection.

## Input fields

| Field                                                                      | Meaning                                                                                                                                                                                               |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `origin`                                                                   | `synthetic` for engineering examples; `supplied` for the external package. Synthetic evidence anywhere in the material proof chain blocks an operational claim.                                       |
| `programme_id`, `target_sha256`, `scope_sha256`                            | Exact programme and canonical target/scope bindings, checked against current programme inputs.                                                                                                        |
| `protocol`                                                                 | Registration ID, exact protocol reference, all relevant amendment record IDs and `original_registered`, `prospectively_amended` or `exploratory` analysis basis.                                      |
| `delivery`                                                                 | Exact action, deviation, verification and accounted-deviation record IDs plus rule IDs/versions. Actual service confirmation is separate from human reports, simulation and independent verification. |
| `source_method`, `design`                                                  | External method/version; design ID/version, registered name, identification basis, description, assumptions and whether independent delivery verification is required.                                |
| `scope`                                                                    | Endpoint, unit, population, geography, pollutant, observation period, coverage, missingness and exclusions, matching the registered target.                                                           |
| `comparative_estimates`                                                    | Canonical decimal strings for `baseline` and `intervention`, or `null` for unavailable values. Never infer a missing quantity.                                                                        |
| `criterion`, `registered_target`                                           | Point estimate, bound or probability interpretation/dependence assumptions, plus target fraction and inclusive/strict relation. Only point-estimate comparisons are implemented.                      |
| `report_refs`, `data_refs`, `external_review_refs`, `expected_output_refs` | Exact immutable originals. All four families are required for a supported comparison.                                                                                                                 |
| `authors`, `uncertainty_interpretation`, `material_limitations`            | Retained external authorship and scientific interpretation; Haze does not authenticate credentials or reproduce the causal analysis.                                                                  |

Decimal inputs permit at most 18 significant digits and 12 fractional places; intermediate integers are bounded to 128 digits. Compare thresholds exactly without rounding. An unsupported bound or probability criterion stays a gap even when its supplied point estimate meets the numerical threshold.

The flat admitted task context is bounded to 64 exact references and programme phase lineage to 72. Evaluation proof traversal is bounded to 128 retained references, with explicit cycle/oversize errors. Each programme supports 32 shared retained context/pilot/delivery/evaluation records within 128 KiB. Larger work requires an explicit split.

## Current-use and history rules

The server rechecks original hashes, identity/mode, source permissions and holds, producer/reviewer provenance and current upstream support. The registered observation period must have ended and the programme must name its scientific owner before operational adoption can qualify. Unknown registration timing, post-outcome target changes, unaccounted material deviations or unresolved material objections block an unconditional registered-target claim.

Withdrawal names the exact prior adoption. Requalification after withdrawal requires a fresh admitted evaluation, independent review and dossier, with explicit supersession. The dossier's scientific reviewer attestation and the new technical products must date on or after the withdrawal; copying old reviewed bytes under a new artifact ID is insufficient. Missing or held withdrawal/resolution evidence cannot resurrect an older qualified claim or erase an open objection. Material objections survive replacement arithmetic until an exact supported resolution is retained.

Current supported below-target evaluation can remain scientifically qualified while `achieved_reduction` is false. Insufficient evidence is also a completed review outcome. Reviewed learning artifacts remain `not_published`; World Model acceptance and H-MEM publication are outside this interface.
