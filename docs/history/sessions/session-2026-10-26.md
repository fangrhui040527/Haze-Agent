## 5. Architecture as it actually is

Two halves, two processes. **"HazeOps" means two different things** (P10):

```
HazeOps (watcher, server/src/hazeops/, :8000)
  reads  -> Open-Meteo/CAMS (live), FIRMS (live), OpenAQ (off), Zetaris (logs in, no queries)
  writes -> WORLD MODEL (facts) -> dashboard draws the map
  no model anywhere in server/ — it is pure code, on a clock

HazeOps (agent, app/agents/hazeops/, :8787)
  reads  -> Zetaris :8888 -> SmokeLedger PG :5433
  writes -> artifacts in the task store -> WorkerShield -> EvidenceCritic
  model-driven, runs only when a task is submitted
```

**The World Model is only ever a destination, never a source.** Nothing reads it as evidence.

### The four assignments

| ---------------------- | -------------- | ------------------------------ |

| `pm25.analyze`         | WorkerShield   | yes                            |

`runtime.ts:1379` short-circuits: an assignment with its own `execute` never reaches the model
loop. `observation-gap` just files an `evidence.gap` artifact saying observation and attribution
are unavailable — which is literally true, because those tables are empty (P6).

### EvidenceCritic's real scope

All in `independentlyCheckPm25` (`app/capabilities/pm25/methods.ts:378`). It re-derives, from the
raw capture and never from the analysis's own numbers:

1. Re-validates raw evidence against the authorized scope (shape, period, semantics, row linkage).
2. Re-scans every value — its own min/max, plus all five counts.
3. Re-enumerates expected hourly slots, merges gaps into spans, re-derives availability status.
4. Checks citation and finding-ID uniqueness, and scope hash equality.

Verdict is `valid = findings.length === 0` — **zero tolerance**. Independence is enforced
**inside the tool** (`index.ts:177`: "A producer cannot independently check its own analysis"),
not trusted to the model. It explicitly does **not** judge prose entailment and never performs
scientific review — both declared as returned limitations. That last point contradicts the deck
(P11).

## 6. Decisions already made — do not re-litigate

### Agents will NOT read the World Model (spike completed, answer is no)

Asked and investigated. Three independent blockers:

1. **It is a snapshot, not a history.** `WmFact` is an append-only log where new readings
   supersede old. The watcher runs every 3 hours (`cadenceSec: 10800`) → 8 readings per place per
   day at best, UI timeline capped at 12 entries. There is **no history for any past date** and
   never will be for dates before the watcher first ran.
2. **No route and no client.** The World Model's only query is `about(id)` — all facts for one
   place, **no period filter**. And `app/` contains no reference to `:8000` at all; a World Model
   adapter would be entirely new code.
3. **The contract forbids it.** `captureSchema` pins `backend: 'zetaris-rest'` and demands
   per-row hourly `start`/`end`, a verbatim `raw` payload up to 512 KB, and
   `selected_raw_row_indices` proving each row came from that payload. The World Model stores a
   projected value, not a raw payload. And EvidenceCritic re-enumerates _hourly_ slots — fed
   3-hourly facts it would mark two of every three hours missing, forever.

**And the decisive fact:** `SOURCE_FILTER = 'open-meteo-air-quality'`. The SmokeLedger `pm25`
table **is Open-Meteo data**, loaded by `npm run smokeledger:fetch:pm25`. Zetaris was never a
different source — it is the same CAMS data stored so it can be queried by period, 33,120 rows
deep instead of 2. So the World Model is a strictly worse copy of what the agents already have.

The sensible direction is the **reverse**: agents keep reading Zetaris, and what they prove flows
_into_ the World Model. `projection.ts:300` already has a Zetaris path
(`PM2.5 … (Zetaris <query>)`), so the destination side is half-built. That is P5 + the optional
work in P16.

### The env file is now wired (was option A, done in `ec83e47`)

Both `start` and `dev` in `server/package.json` now load
`../third_party/zetaris/.env.local` after the root `.env`. The two files share **zero keys**, so
load order is immaterial. This also replaced the stale `ZETARIS_BASE_URL` default of
`localhost:3000` (taken here by an unrelated dev server) with the configured `localhost:3002`.

## 8. Traps already paid for — do not re-learn these

- **`TaskStop` / killing npm does not kill node.** The npm wrapper dies and the child keeps the
  port. Symptom: a restarted server loads its new config, runs its watchers, then exits because
  the port is taken. Check the orphan's command line before killing it so you do not take down an
  unrelated dev server:
  `Get-CimInstance Win32_Process -Filter "ProcessId = <pid>" | Select-Object CommandLine`
- **`$TMPDIR` is unset in this Bash.** `cmd > "$TMPDIR/x.log"` resolves to `/x.log` and dies with
  "Permission denied". Use an explicit path.
- **The Read tool cannot open PDFs here** — no poppler (`pdftoppm is not installed`), and Python
  has no pypdf. A working extractor for the Skia/Chromium PDFs (`Haze.pdf`,
  `SmokeLedger_Pitch.pdf`) is preserved at **`tools/pdftext-skia.mjs`**:
  `node tools/pdftext-skia.mjs "C:\Users\USER\Downloads\Haze.pdf"`.
  Those files store text as **single-byte glyph IDs** with **per-page** font resources (93 fonts
  in the deck, names like `/F5` reused across pages), so both the CMap lookup and the per-page
  font resolution are required — a global font map yields garbage, and a 2-byte code step yields
  nothing at all. The older ReportLab extractor for
  `docs/Haze_Agent_Architecture_v0.13.pdf` is a different problem (ASCII85+Flate) and does not
  work on these.
- **Zetaris REST needs more than SQL.** Body requires `queryId`, `sql`, `source: "SqlEditor"` and
  `limit`; the `X-Request-ID` header must be a **UUID** or it rejects with
  `Invalid value for: header X-Request-ID`. A login `idToken` works as a Bearer on `:8888`, which
  is the fast way to tell a bad API key apart from a broken platform.
- **Zetaris API keys live in the metastore**, so a key made against another instance fails here
  with HTTP 400 `{"msg":"Not Allowed"}` — not the 401 the docs describe. A human must recreate it
  at Management → API Tokens → +; agents are forbidden from creating or fetching it.
- **`POST /api/tasks` enforces same-origin.** Send `Origin` matching the host you actually used —
  `http://[::1]:5173`, not `http://localhost:5173` — or you get 403 `same_origin_required`. Also
  needs `Content-Type: application/json` and a stable `Idempotency-Key`.
- **Bash heredocs eat backslashes here.** Writing a script with regexes via an inline heredoc
  corrupts them. Use the Write tool or a quoted heredoc (`<< 'EOF'`).
- **A paused task is not a hang.** `outcome: 'unknown'` (network failure, containers down) pauses
  the branch awaiting explicit resume and keeps the attempt charged. `outcome: 'unavailable'`
  (missing key) completes with an `evidence.gap` artifact and `support: 'gap'`. Both are correct
  behaviour.
