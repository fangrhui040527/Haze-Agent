# Orchestration component adapters

`app/orchestration/ports.ts` is the shared asynchronous integration boundary for the Manager and specialists. Each call receives server-owned task/assignment IDs, objective revision, numeric generation, principal/workspace, absolute deadline and an abort signal. Model turns additionally receive `modelLimits: { maxInputBytes, maxOutputTokens }`. These are execution context, not permissions; the coordinator admits capabilities and charges budgets before calling a port. Components must reject cancelled or expired work. The supplied wrappers also stop waiting for components that ignore cancellation; remote termination and billing are not guaranteed.

| Component   | Port                           | Required behavior                                                                                                                       |
| ----------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| NightShift  | `execute(input, context)`      | One bounded model turn returning text and the actual response receipt. No routing, retries or budget ownership.                         |
| Zetaris     | `retrieve(scope, context)`     | The exact bounded PM2.5 selection, raw response, query/request receipt, selected raw-row indices, units, timing and limitations.        |
| H-Mem       | `recall(query, context)`       | Eligible reusable lessons with an immutable version/hash, or explicit unavailability. Recalled content is context rather than evidence. |
| World Model | `readSnapshot(query, context)` | A bounded versioned domain snapshot, or explicit unavailability. This port exposes no canonical-state writes.                           |

`createLivePorts(env, source?, model?)` wraps the existing `EvidenceSource` and `AgentModel` interfaces. Provider resolution is lazy, so missing configuration fails the attempted work rather than API startup. This wrapper is an integration route for the existing provider; it does not claim that the NightShift service is already connected. Replace `ports.nightshift` with the teammate's adapter when available. Existing provider timeout, size bounds and credential handling remain in force. There is no automatic source, provider or fixture fallback.

Model receipts distinguish returned model/response IDs from the configured route. Missing IDs or token counts stay `null`; counts must be nonnegative safe integers. An older model adapter exposing only `complete` receives an all-null receipt. A malformed receipt fails validation rather than becoming reported usage.

`NightShiftPort.selection` optionally reports the configured provider/model route; it never substitutes for provider-returned metadata. The lazy live factory exposes it after model resolution, or immediately when a model was explicitly injected. A NightShift implementation must reject oversized JSON model input and apply `maxOutputTokens` to the actual provider request. The configured-model HTTP adapter has a fixed 700-token request cap: its wrapper accepts per-turn caps of 700 or higher and rejects smaller caps before requesting work. Reported output usage above the grant fails validation; absent usage remains unknown. Input bytes count the UTF-8 JSON `AgentModelInput`, before provider-specific transport framing.

Available enrichment returns `{ status: 'available', ref: { id, version, sha256 }, content, limitations }`. `version` identifies the exact immutable snapshot or record, not an entity schema revision. `sha256` hashes the exact content using the existing Haze canonical JSON serializer (`contractHash`). Content must be bounded JSON and at most 65,536 UTF-8 bytes in canonical form before hashing or persistence; readback must match the hash. The coordinator can treat an oversized optional snapshot as unavailable with an explicit receipt. An unavailable result supplies a concrete reason. The default H-Mem and World Model adapters are unavailable, allowing evidence execution to proceed with explicit gaps.

`captureReviewedLesson` is separate from recall. Its default result is `disabled`; a model critic's approval alone does not establish human eligibility. No automatic lesson capture or World Model mutation is enabled by these adapters. The existing pinned Meterless facades remain unchanged; a teammate can wrap those or a remote implementation behind these asynchronous ports.

## Fixtures and conformance

`createFixturePorts` is an explicit test/development factory. It never reads live credentials or issues network requests. Callers inject the model executor so the capability owns its five role-specific payloads; no default model answer is substituted. Its default evidence capture supplies synthetic hourly modeled values and exact raw-row linkage. The legacy `EvidenceCapture.mode` type is fixed to `live`; **the port's `mode: 'fixture'` is authoritative for execution provenance**. Persisted task/results must therefore use the port mode and retain the synthetic limitations.

The Vitest-independent helpers in `app/orchestration/conformance.ts` check cancellation, explicit adapter identity/mode, response metadata, source/scope linkage and enrichment hashes. Each helper makes one successful call plus a pre-cancelled call, so use fixture adapters for local checks; running one against a live adapter is an explicit live integration test. The harness establishes boundary compatibility, not scientific correctness, live data coverage, distributed fencing or remote exactly-once execution.

Run the local adapter tests with `npm test -- tests/unit/orchestration-ports.test.ts`. New adapters should pass this contract harness and their own transport/authentication tests before the team replaces the configured fixture or live route.
