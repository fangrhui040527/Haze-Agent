# Malaysia Environmental USL: Table Architecture

The sources use a mixture of REST federation and local FileStore tables.
Open-Meteo air quality and wind are federated directly from per-location REST
tables; no local snapshot or PostgreSQL ingestion is involved.

## Raw table topology

| Data source | Raw tables | Storage and refresh |
| --- | --- | --- |
| Open-Meteo air quality | One REST table per selected location | Generated by `sources/air_quality/fetch_air_quality.ts`; queried through Zetaris |
| Open-Meteo wind | One REST table per selected location | Generated by `sources/open_meteo_wind/fetch_open_meteo_wind.ts`; queried through Zetaris |
| NASA POWER climate | One REST table per selected location | Coordinate/date-keyed endpoints with a generated union view |
| Data.gov.my weather | One `forecasts_raw` REST table | Nationwide response queried through Zetaris |
| NASA FIRMS fires | One `active_fires` FileStore table | Downloaded CSV with location matching, published by the FIRMS source |
| Windy point forecast | Two FileStore tables | One GFS and one CAMS CSV snapshot for the configured point |
| Location dimensions | Two FileStore tables | Canonical location and administrative-code reference files |

The physical count depends on which sources and per-location tables are
registered. `--test` limits these sources to Kuala Lumpur; full registration
creates one REST table per canonical location.

## Stable views and task consumption

`air_quality.hourly_observations` exposes the normalized API response. Its
fields include `location_name`, requested coordinates, UTC `observation_time`,
and PM2.5/PM10 values. The current PM2.5 task queries this base view directly.
An environmental USL activation may consume the same view, but that separate
model lifecycle is not a prerequisite for the task.

`open_meteo_wind.hourly_observations` exposes 10 m and 850 hPa winds as `u`/`v`
components with their location and valid time.

The environmental USL declares separate `open_meteo_pm25_obs` and
`open_meteo_wind_obs` tables for these live sources. If `malaysia_env_usl` was
already deployed before those declarations were added, `COMPILE USL IF NOT
EXISTS` will leave its existing model unchanged; update or replace that model
before running the corresponding activation statements.

## Refresh boundary

Queries can contact Open-Meteo through Zetaris. Run `npm run zetaris:fetch:pm25`
or `npm run zetaris:fetch:wind` to register the per-location REST tables and
unified view. Both commands accept repeated `--location` IDs and an offline
`--dry-run` preview. Use `--test` to limit setup to Kuala Lumpur.

Data.gov.my and NASA POWER retain their REST access paths. Filtering by
location and date may reduce upstream requests only where Zetaris supports
predicate pushdown; verify actual API usage on the target instance.
